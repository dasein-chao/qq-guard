## 二、整体架构与技术选型

```
QQ 群消息
   ↓  OneBot v11 (NapCat 协议端，旧手机或本机)
[1] 消息接收层  → WebSocket 客户端，断线重连
   ↓
[2] 存储与去重  → SQLite，原始消息全存，P0/P1 长期留存
   ↓
[3] 基础规则过滤 → 明显 P3（表情/重复/广告）直接排除，减少 AI 调用
   ↓
[4] AI 理解与分类 → P0/P1/P2/P3 四级 + 结构化字段抽取
   ↓
[5] 提醒与摘要   → P0/P1 即时推送；P2 进日报；P3 静默
   ↓
[6] 手机推送    → Webhook 到手机（企业微信 / Server酱³ / Bark）
   ↓
[7] 模型管理入口 → 本地网页，可视化切换主/备模型
```

**技术选型**：
- 后端：Python 3.13 + 标准库 + websocket-client + Flask（轻量本地网页）
- 存储：SQLite（已在用）
- 管理界面：**本机浏览器打开 `http://127.0.0.1:端口`**，一个本地网页，满足"可视化入口，不改配置文件"的要求
- 手机推送：Webhook（不依赖邮箱配置，手机端 App 有推送）

## 四、AI 模型调用与可视化切换（关键约束）

### 4.1 已确认的事实
平台模型目录里，你指定的三个模型**都存在且启用**：

| 模型 ID | 名称 | 积分倍率 | 备注 |
|---|---|---|---|
| `glm-5.3-flash` | GLM-5.3-Flash | x0.08 | 你指定的主模型候选 |
| `deepseek-v4.1-flash` | DeepSeek-V4.1-Flash | x0.11 | 你指定的备用模型候选 |
| `hy4flash-free` | Hy4 flash | **x0.00 免费** | 测试阶段可用，不耗积分 |

### 4.2 必须说清的障碍
WorkBuddy 平台的免密钥 LLM 通道是给 **Web 应用 / 小程序**设计的：
- 调用需要 `endpoint` + `publishableKey`，且服务端校验 Origin（域名）
- 官方只提供 JS/TS SDK（`@tencent-ai/workbuddy-cloud-sdk`），**没有 Python SDK**
- 该通道绑定具体应用，需要开通云服务环境（这一步会触发 UI 确认，且可能有配额/计费影响）

**这意味着**：一个常驻本机、独立运行的 Python 程序，**不能直接调用平台免密钥模型通道**。

### 4.3 三条可行路线（需你选一条）

**路线 A：自建本地 Web 应用（推荐，最贴合你的需求）**
- 把监控后台做成一个本地 Web 应用，用平台的 Web SDK 调用模型
- 模型管理界面天然就是网页，符合"可视化切换"要求
- 缺点：需要开通云服务环境（UI 会弹确认），模型调用走平台额度；程序以浏览器/本地服务形式运行，常驻方式要设计

**路线 B：用你自己的模型 API Key**
- 你在 DeepSeek / 智谱 / 硅基流动等平台申请 API Key（按量付费，用多少付多少）
- Python 直接调用，独立运行无障碍
- 缺点：要你自己注册账号、充值；"每日赠送积分"用不上

**路线 C：混合**
- 分类用免费/低倍率模型跑，重要决策切平台模型
- 缺点：复杂度最高

**我的建议**：路线 A。但要你明确同意开通云服务（这会让 UI 弹确认框），并接受"模型调用走平台额度"。你之前说"不必过度节省 Token，优先保证识别质量，同时避免重复调用，不得未经同意产生额外付费"——路线 A 符合"走已有额度、不额外付费"，但需要确认额度归属。

## 七、目前无法实现或存在限制的功能（如实列出）

1. **平台免密钥模型无法被独立 Python 程序直接调用**——这是本方案最大的技术约束，必须由你选路线解决。
2. **私聊不监控**——按需求执行，不读取、不分析、不摘要、不代回。
3. **不能保证 100% 不封号**——非官方接入的固有风险。
4. **好友/群关系无法自动迁移**——封号换号需手动加回。
5. **图片/文件默认不下载**——只保留元信息，重要事件才处理。
6. **电脑睡眠/关机时无法收消息**——本机运行方案的物理限制；可用充电宝+旧手机方案缓解。
7. **"结合前后文识别真实意图"**——需要把同一群最近 N 条消息一起送进模型，会增加 Token 消耗；实现时会做窗口大小可配。
