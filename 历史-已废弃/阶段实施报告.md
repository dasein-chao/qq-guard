## 六、遇到的问题、原因和解决办法

1. **重复消息漏判**：只存一条最近消息指纹，被中间消息覆盖。改为 `deque` 保存最近 20 条，按相似度阈值比较。修复后测试通过。
2. **上下文 key 不一致**：样例只有 `group_name` 没有 `group_id`，导致所有群共用 default key。改为 `group_id or group_name or default`。
3. **测试脚本把 property 当方法调用**：`c.available()` 报 TypeError。测试脚本改为 `c.available`。代码本身无问题。
4. **桥接服务首次启动失败**：用 `&` 启动的进程被 shell 清理。改用后台任务方式启动，服务正常监听。
5. **摘要测试用 any() 可能掩盖 deadline 未抽取**：单独复查了 P0 记录的 deadline 字段，确认带"截止"字样的消息确实抽到了时间，无截止字样的标"待核实"。
6. **备份恢复导致数据库损坏（严重，已修）**：回归测试时 `messages.db` 报 `database disk image is malformed`。定位原因：SQLite 处于 WAL 模式，旧备份逻辑直接 `copy2` 主库文件，未 checkpoint 的事务在 `-wal` 里，恢复后索引页不完整。**修复**：改用 `sqlite3.Connection.backup()` 生成一致性快照，并在备份后立即跑 `PRAGMA integrity_check`。用迁移前的健康备份恢复了主库（8 条数据，已自动迁移为 P0/P1/P3），重跑 26 项测试全通过，主库完整性检查为 `ok`。
